# 产品成长路线

> 目标：从会提需求，升级到能发现问题、定义方案、推动交付、验证结果的产品能力。

## 8 周路线总览

| 周次 | 主题 | 关键任务 | 周产出 |
|---|---|---|---|
| 第 1 周 | 产品基础 | 理解用户、场景、需求、方案、指标 | 产品术语表 |
| 第 2 周 | 用户与需求 | 访谈、观察、问题拆解、需求分层 | 10 个用户问题 |
| 第 3 周 | 竞品分析 | 拆功能、流程、定位、商业模式 | 3 份竞品拆解 |
| 第 4 周 | PRD 写作 | 写背景、目标、流程、规则、验收标准 | 1 份 PRD |
| 第 5 周 | 原型与流程 | 画用户流程、页面结构、核心状态 | 1 个低保真原型 |
| 第 6 周 | 数据与指标 | 定义北极星指标、转化漏斗、埋点 | 指标追踪表 |
| 第 7 周 | 项目协作 | 评审、排期、验收、上线、反馈 | 交付检查清单 |
| 第 8 周 | 复盘迭代 | 基于数据和反馈做版本决策 | 产品复盘报告 |

## 每日 2-8 小时模板

| 投入 | 时间结构 | 适合任务 |
|---|---|---|
| 2 小时 | 40 分钟学习 + 60 分钟拆解 + 20 分钟记录 | 忙碌保底 |
| 4 小时 | 1 小时学习 + 2 小时实操 + 1 小时复盘 | 标准推进 |
| 8 小时 | 2 小时学习 + 4 小时产出 + 2 小时评审迭代 | 周末冲刺 |

## 产品清单

- [ ] 写清楚目标用户是谁。
- [ ] 写清楚用户在什么场景下遇到问题。
- [ ] 区分用户想要的方案和真实要解决的问题。
- [ ] 给需求标优先级：必须做、应该做、可以做、不做。
- [ ] 为每个功能写验收标准。
- [ ] 定义上线后看什么指标。
- [ ] 每周至少复盘 1 次需求判断是否正确。

## PRD 模板

| 模块 | 内容 |
|---|---|
| 背景 | 为什么现在要做 |
| 目标 | 解决什么问题，用什么指标判断 |
| 用户 | 谁会使用，使用频率如何 |
| 场景 | 用户在什么情况下进入 |
| 流程 | 从进入到完成的关键路径 |
| 规则 | 边界、异常、权限、限制 |
| 验收 | 开发完成后如何判断可上线 |
